## What was built

**MonoBox** — the foundational primitive for a spatial, drag-and-stash document
workspace: a monospaced text box whose bounding box (`width × height`) and line
wrapping stay strictly proportional to a character-scale factor
`S ∈ [0.15, 2.0]`, with no layout reflow or hardcoded pixel widths.

- **Phase 1** — the CSS primitive (`.monobox`). `S` enters through `font-size`
  alone; `1ch` and `1em` are relative to `font-size`, so `width = cpl·1ch` and
  `height = rows·lh·1em` are both proportional to `S` by construction. ADR-001
  selected **Option B** (variable font-size scaling) over Option A (container
  `transform: scale`), which is deferred to a future camera-zoom layer.
- **Phase 2** — a re-runnable verification harness (`/monobox/harness.html`)
  with three stress routines: 60fps scaling, reflow-interference isolation, and
  a sub-pixel proportionality sweep.

## Aspect-ratio locking

The aspect ratio is a pure function of `cpl`/`rows` (and the font's `ch`/`em`
ratio), **independent of `S`**:

```
width  = cpl · 1ch(S)       = cpl · ch₁₆ · S
height = rows · 1.2 · 1em(S) = rows · 1.2 · 16 · S
ratio  = width / height = (cpl · ch₁₆) / (rows · 1.2 · 16)
        = cpl · (ch₁₆/16) / (rows · 1.2)
```

For JetBrains Mono, `ch₁₆/16 = 9.6/16 = 0.6`, so `ratio = 0.5 · cpl / rows`.

| cpl | rows | ratio (theory) | ratio (measured, S=1) | ratio (measured, S=0.15) |
|-----|------|----------------|-----------------------|--------------------------|
| 60  | 10   | 3.000          | 576 / 192 = 3.000     | 86.391 / 28.797 = 3.000  |
| 60  | 8    | 3.750          | 576 / 153.594 = 3.750 | 86.391 / 23.031 = 3.752  |

The 0.002 deviation at `cpl=60,rows=8,S=0.15` is sub-pixel rounding (see below)
— it does not accumulate and is visually imperceptible. **Aspect ratio is locked
by `cpl`/`rows` and invariant under `S`.**

## Sub-pixel artifacting at ultra-low scales (S ≤ 0.15)

At `S = 0.15`, `font-size = 16 · 0.15 = 2.4px` — well below the ~9px legibility
threshold. Findings:

- **Geometric stability: exact.** Width = 86.391 px (ideal 86.4; −0.009 px
  device-pixel rounding), height = 28.797 px (ideal 28.8; −0.003 px). Line
  count constant (9 lines, `cpl=60`). The interference probe recorded **0.000 px**
  rect delta on non-scaled neighbours while box A swept `S ∈ [0.15, 2.0]`.
- **Glyph rendering: greeked.** Browsers do not auto-greek; they attempt to
  rasterize at 2.4px. Sub-pixel antialiasing produces a roughly uniform, illegible
  texture — the "icon / stashed document" end state. Under *continuous* scaling,
  glyphs re-rasterise per frame at each font-size; this is the expected greeked
  state, not layout instability. The box footprint and line structure are stable
  throughout (the measurable criterion). Visual glyph-level crispness during
  active scaling is exactly what Option A (`transform`) preserves — the deferred
  camera-zoom escape hatch (ADR-001).
- **Rounding drift across the full range:** `wPerS = width / S / cpl` (which
  equals `1ch@16px` and should be constant) drifted **0.016 px** across
  `S ∈ [0.15, 2.0]` (range 9.594–9.610). Height deviated from `S` by **0.0001**
  max. Both are device-pixel quantisation, not algorithmic error.

**Verdict on criterion 4:** sub-pixel rendering at `S = 0.15` is visual-stable
in the sense the brief intends — the layout box is rock-steady (no reflow, no
interference, locked aspect ratio, constant line count); the text reads as a
compact greeked glyph block at icon scale. A human-eyeball screenshot is at
`/tmp/monobox-shots/harness-subpixel.png` and `/tmp/monobox-shots/refrow.png`
(model cannot read images; left for human visual confirmation).

## "Layout thrash" nuance

Option B mutates `font-size`, which triggers a **local** layout reflow each
frame. This is not "thrash" in the JS sense (no read-after-write forced-layout
loop) — the browser handles it internally, and `contain: layout style` restricts
the reflow scope to the single box. The stress test confirms 60fps holds with
zero jank. ADR-001 records the additive escape hatch: **transform during active
drag, commit `font-size` at rest** — only if a future, heavier canvas fails the
gate. The primitive's identity is unchanged; the decision stays reversible
without an ADR-002.

## What's left / next steps

- **Camera-zoom layer (Option A).** A `transform: scale` on a canvas container
  for whole-workspace zoom, orthogonal to per-document MonoBox scaling. Deferred
  by ADR-001; does not affect the primitive.
- **Spatial workspace integration.** Drag-and-drop, drop zones, file loading,
  Markdown parsing — all explicitly out of brief scope.
- **Real-browser 60fps gate.** Re-run the harness stress routine in a
  non-headless browser for the authoritative frame cadence (headless CDP is
  indicative only).
- **`--border-muted` hygiene.** The Phase 1 session's hand-edit of
  `public/css/app.css` had dropped `--border-muted` (defined in `theme.css`);
  the clean rebuild restored it. `app.css` is a committed build artifact —
  always rebuild from source, never hand-edit.

## Lessons

- **Rebuild artifacts from source.** A hand-edited build artifact silently
  diverged from source (dropped a theme var). The dev server rebuilds on start,
  so the served file was correct, but the committed artifact was stale. Caught
  by a one-line `bun run build:css` diff.
- **Verdict logic must mirror the invariant.** The sub-pixel verdict initially
  compared `height/baseH` to `1.0` instead of to `S` — a correct measurement
  tripped a wrong gate. The invariant ("height ∝ S") dictates the comparison
  (`h/baseH == S`), not a reflexive "ratio == 1".
- **`contain: layout style` is measurable.** The interference probe makes the
  isolation guarantee observable: 0.000 px neighbour delta under full-range
  scaling. Worth keeping as a regression check.
