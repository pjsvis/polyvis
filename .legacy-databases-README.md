### `bento_ledger.sqlite` (64 KB)

**Status:** ✅ Active (Content Deduplication Ledger)
**Purpose:** Maps content hashes to stable Locus IDs for "Bento Boxing" (content fragmentation)

**Schema:**
- `bento_map` table (343 rows)
- `canon_hash` (TEXT, PK) - MD5 hash of content
- `locus_id` (TEXT) - UUID for deduplicated content
- `created_at` (TEXT) - Timestamp

**Used by:**
- `src/data/LocusLedger.ts` - Deduplication service
- `src/core/BentoBoxer.ts` - Content fragmentation
- `src/pipeline/Ingestor.ts` - Data ingestion

**How it works:**
1. Content is hashed (MD5)
2. Hash is looked up in bento_map
3. If exists, return existing locus_id (deduplicated)
4. If new, mint UUID, store mapping, return new locus_id

**Keep or delete?**
- **Keep** - Actively used by content pipeline
- **Regenerates** - Can be rebuilt from source content if lost

**To inspect:**
```bash
bun run inspect-db bento_ledger.sqlite
```
